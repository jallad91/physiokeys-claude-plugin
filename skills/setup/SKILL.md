# Set up PhysioKeys

Read [the evidence and tool contract](../../references/evidence-workflows.md) and [the library and chat guide](../../references/library-and-chat.md) first. Setup helps users connect and choose a useful task without spending a search just to demonstrate installation.

1. Preserve the current conversation's task. In a fresh conversation, briefly explain that PhysioKeys searches rehabilitation research, reads abstracts and available licensed full text, supplies citations, and can save requested PMIDs to the user's private library. State that requests must be de-identified general research questions. Do not solicit clinical records or identifiers.
2. If the PhysioKeys account tool is available, call `physiokeys_account_status` once to verify access. If unavailable, unauthorized or expired, direct the user to connect PhysioKeys from this plugin's **Connectors** tab (or **Customize** › **Connectors**), complete the PhysioKeys sign-in in its secure flow, then retry only after the user has connected. On Team and Enterprise plans an Owner adds the connector first. The server URL is `https://app.physiokeys.com/api/mcp` if a custom-connector form asks for it. Do not create a second connector for the same server. Never ask for passwords, access tokens or codes in chat, and do not claim a connection succeeded without a successful tool result.
3. Explain the actual returned allowance when known: each research search and continuation uses one normal PhysioKeys search. Opening saved papers, filtering their titles, picking or attaching a citation, reading article details and checking account status do not consume search allowance; saving counts toward saved-article capacity. Rate limits still apply. Explain the [source-selection policy](../../references/evidence-workflows.md#source-selection-and-pubmed-approval). Research effort follows the question through the [adaptive budgets](../../references/evidence-workflows.md#adaptive-search-and-reading-budgets): quick briefs stay small, while explicit deeper reviews can screen and read more within stated bounds. Result pages support up to 50 only where the live connection advertises it; respect smaller schemas and user/remaining allowances. Do not promise unlimited use, quote invented plan amounts, initiate checkout or promote an upgrade.
4. If searches are exhausted, explain that new searches cannot run. A provided PMID or relevant saved articles can still be read with the free tools. Do not claim those sources exist until returned. If the status call fails, report allowance as unknown.
5. Offer a free first action: open **Saved papers** in **Research Library** when the `physiokeys_research_library` tool is connected. Explain **Filter by title** (free) versus the **Research** tab (**Uses 1 search**). Ticking papers adds them to **Papers for Claude**; **Ask Claude to compare these** and **Ask Claude to appraise this** put an editable question in the message box for the user to review and send. Follow the library and chat guide for capability checks, evidence-access labels and fallbacks. Do not promise the view where it is unavailable, guess a tool name, attach library contents, save a paper, or run a demonstration search automatically. With only the original tools available, offer to list saved papers on request and fetch a selected identifier.
6. When there is already a clear, authorized research task, continue with the appropriate skill rather than asking the user to repeat it. A saved-paper or supplied-ID task can use free reads even with no search allowance. The research skills follow the [exact-article full-text fallback](../../references/evidence-workflows.md#exact-article-full-text-fallback) if more text is needed and host access is allowed:
   - [evidence-brief](../evidence-brief/SKILL.md): a concise answer to a rehabilitation research question.
   - [compare-interventions](../compare-interventions/SKILL.md): an evidence-based comparison of alternatives.
   - [paper-appraisal](../paper-appraisal/SKILL.md): journal-club appraisal of a particular paper.
   If the user asked only for setup, offer saved-paper browsing first, then these three research workflows. Do not run a demonstration search or save papers automatically.
7. The final setup response contains three parts: **connection and allowance** (verified values, or explicitly unknown), **costs** (research searches/continuations spend allowance; saved-paper browsing/filtering, citation selection/attachment and article/account reads do not; saves use saved capacity), and **next action** (continue the existing task, or offer the free saved-paper action and research workflows). Include the costs even when the user asked only for setup. Keep the response short; explain Research Library details when useful for the next action. Setup verification is connection/allowance verification, not proof of research quality, rendered extension support or completion of a clinical review. Private notes, tags and uploaded PDFs remain outside these tools' capabilities.
